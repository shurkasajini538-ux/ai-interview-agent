# 代码讲解与答辩准备

这是阅读路线与练习提纲，不代替参赛者亲自理解、运行与解释代码。

## 阅读路线

1. README → app.py：先启动应用，找到导入、创建练习、提交回答、下一题和导出的 API。
2. frontend/src/pages/Interview.tsx → store.ts：跟踪输入草稿、后台任务与 SSE 如何更新页面。
3. studio/interview.py：从 model_context 到 request_json，确认模型收到哪些内容，以及如何校验题目、分数和引用。
4. studio/agent.py：看三个工具的定义、模型tool_calls、参数检查、工具结果回传与次数限制。
5. studio/knowledge.py：手工取一段简历，查看430字符分块、70字符重叠、来源ID、TF-IDF和排名融合。
6. studio/jobs.py → runtime.py → storage.py：解释请求去重、取消与事务保存之间的关系。
7. tests/test_upgrade.py 与 verification：把每个技术主张对到测试或实测记录。

## 常见问题

**为什么需要AI？** 在线模型根据岗位、简历与当前回答选择问题和追问，并组织评分建议；检索提供依据、校验约束结果。无Key时规则模式用于基础练习和运行验证，二者明确区分。

**这算Agent吗？** 是有界工具调用流程：模型选择工具，程序校验并执行，把结果送回模型。没有自由执行系统命令或任意网页操作，也未集成未使用的框架。

**为什么不是简单把整份简历放进提示词？** model_context提供摘要与少量索引片段，工具可按需追加检索；来源位置可回查。不要声称完全不发送任何摘要，也不要把稀疏向量叫神经语义向量。

**评分可靠吗？** 程序保证分项范围、总和和引用位置，不能保证模型判断完全正确。评分是练习参考，教师仍应核对技术准确性；不同引擎的分数不直接比较。

**怎样避免伪造经历？** STAR只接受回答原文片段，缺失事实标记待补。该约束保证整理内容来源，不证明用户输入本身是真实经历。

**取消是否立即停止计费？** 不能保证。取消协作地阻止后续步骤与保存，已发送的网络请求可能仍由供应商处理。

**检索有没有提升？** 当前12条自制查询各方法都命中，小样本没有显示差异。需要增加同义改写、干扰段落和无匹配难例，不能宣称提升率。

**有多少用户？** 真实试用尚未完成，不能把浏览器自动测试或示例简历当作真人用户。试用方案已准备，反馈由愿意参与的学生或教师实际提供。

**为什么不直接部署公网？** 当前本机架构没有完整账号认证、限流和费用隔离。公网是可选扩展，先完成本机可复现版本。

**和参考仓库有什么关系？** 参考了多格式入口、结构化展示与材料组织；核心代码重构实现，未复制对方权重、私人数据或密钥，来源已说明。

## 建议本人现场操作

在无Key模式完成一次练习并导出；修改简历后说明旧练习为什么不变；重答一次并找到旧尝试；解释一次模型失败回退；手动计算四项总分；在代码中指出未知工具为何无法执行。
