# 2.0.1 可靠性修订

日期：2026-10-15。基于2.0.0候选版继续修复，沿用codex/competition-upgrade分支。

## 修复内容

- 无匹配或空查询现在返回空证据列表。哈希向量碰撞不能单独成为命中依据；界面进度明确提示无证据时参考摘要。单字母技术名C、R可以参与匹配。仍为词面稀疏检索，不宣称新增神经语义能力。
- 缓存先读取并验证版本、来源位置和数据结构，命中时不重新计算向量。首次并发写入使用幂等替换；坏JSON自动重建，损坏或不可写的可选缓存不阻断内存索引。缓存格式升级自动重建，不改变简历和练习记录。
- 后台任务全局最多8个活动任务，每个浏览器空间仍最多2个；已完成记录与活动记录合计最多100个。去重请求在容量满时仍返回原任务。启动线程失败释放活动容量；最终完成状态与取消检查使用同一锁。
- 浏览器禁用localStorage时，仍能完成当前页面的出题、回答和追问。跨刷新恢复需要浏览器允许存储；临时网络错误保留恢复编号，收到明确404才清除。
- 验收服务支持STUDIO_TEST_PORT，避免测试端口与其他本机服务冲突。

## 验证

后端38项通过；前端TypeScript检查与生产构建通过；浏览器16组通过，页面异常0。新增覆盖无关检索/哈希碰撞、缓存复用与损坏恢复、6路并发首次缓存写入、任务全局容量与释放、记录上限、线程启动失败、禁用浏览器存储与临时连接恢复。

测试使用模拟数据与独立临时数据库，没有调用付费模型来验证这轮基础可靠性修复。历史在线实测和12条检索实验仍对应原候选版，不能当作本次新增效果研究。
