|---|---|---|---|
| AI 技术深度 | 35% | 在线 LLM、结构化输出、校验、追问、历史薄弱点、本地 OCR、离线兜底 | 自主规划和工具调用不足；检索方案与对照实验薄弱 |

### AI 技术细分

- 大模型集成（8%）：已有真实在线调用与结构化约束，可补充模型选型、提示词优化实验与成本数据。
- Agent / 工作流（8%）：已有可恢复的固定题目流程。尚未实现模型决定检索、读取历史、请求补充事实等工具调用。
- RAG（6%）：已有分块、关键词 / 字符片段检索，且检索内容参与追问和评分；但同时仍发送较长简历全文。不能据此宣传为完整向量知识库 RAG，也尚无检索增强收益实验。
- 多模态（5%）：图片和扫描 PDF 经本地 OCR 进入文本面试流程，属于基础多模态输入。无语音或视频；并不意味着必须同时补齐所有模态。
- 安全与可控性（4%）：已有联系方式隐藏、密钥保护、输出格式校验、引用核对、事实保真和降级提示。这是可重点展示的已有优势，但仍需针对性测试提示注入等场景。
- MCP / 工具集成（4%）：尚无 MCP 或 Function Calling。引入有实际价值的工具调用即可，不必为了名称同时堆叠两套技术。

## 推荐修改顺序

### 第一优先：完成提交基础

建立新产品 Git 仓库、保留后续真实提交，补团队信息、环境变量配置和模板，整理视频脚本与 PDF 文档结构。

### 第二优先：增加能证明的 AI 深度

让模型在受控范围内调用「检索简历证据」「读取薄弱点」「记录待补事实」等工具。把题目、追问、评分和证据关联起来，设计少量可复现样本，比较有无检索、不同检索策略的结果。

### 第三优先：提升前端工程

保留现有后端与产品流程，将前端逐步迁移为 React + TypeScript + Vite 等主流方案。拆分页面和组件，引入规范状态管理、渐进式输出或明确阶段状态、路由懒加载与性能验证。

这属于提升得分匹配度的建议，不应写成规则强制要求 React。

### 第四优先：建立差异化和真实反馈

聚焦「本科生项目经历表达与事实核验」：帮助用户区分真实成果、缺失事实和表达问题。邀请真实学生与教师试用，记录问题相关性、反馈有效性、虚构事实控制与使用前后变化，避免仅用自动测试数量证明教学效果。

语音练习和公网演示可以在上述基础稳定后增加，不优先开发无关薪资预测、招聘排序或视频生成。
